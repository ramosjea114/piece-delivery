1. PRODUCT DEFINITION

Build a Windows desktop application that acts as a local bilingual AI translation layer over the user’s screen.

Primary use case:

A Japanese PowerPoint presentation, PDF, browser page, Teams meeting, or other visible Windows content is displayed.

The application continuously observes the screen locally.

When meaningful visual/text changes occur:

Windows screen
      ↓
local screen capture
      ↓
OpenCV change detection
      ↓
frame stabilization
      ↓
local OCR
      ↓
text + bounding boxes
      ↓
translation cache
      ↓
local Qwen API
      ↓
structured translation
      ↓
spatial overlay

The translation must appear near the original source text, similar to localized/transcribed Korean television content, but spatially anchored to the detected source text.

Example:

          今後のプロセス安全活動について
          Future Process Safety Activities

or:

事故防止のための新しいプロセス
New processes for accident prevention

The Japanese remains visible.

The English translation is rendered by the application in a transparent overlay positioned relative to the original OCR bounding box.

The application must also support the reverse direction:

English → Japanese
Japanese → English

The source/target language should be configurable, with an auto source-language mode.

10. CHANGE DETECTION

Do not OCR every frame.

Use OpenCV.

Basic pipeline:

current frame
      ↓
resize
      ↓
grayscale
      ↓
blur
      ↓
absolute difference
      ↓
threshold
      ↓
changed-pixel ratio

Example conceptual threshold:

change_ratio > 0.015

Make it configurable.

Configuration:

change_detection:
  threshold: 0.015
  downscale: 0.25

The exact threshold must be tuned experimentally.

Avoid hard-coded assumptions about a specific screen resolution.

11. FRAME STABILIZATION

Presentation slides often animate or render in stages.

Do not OCR immediately after every detected change.

Require several sufficiently similar frames before processing.

Example:

stabilization:
  stable_frames: 3
  interval_ms: 150

Concept:

Frame changed
     ↓
wait
     ↓
compare
     ↓
stable?
  NO → wait
  YES
     ↓
OCR

This prevents:

* half-rendered text
* animation artifacts
* duplicated OCR
* unnecessary LLM calls

16. QWEN PROMPT DESIGN

Qwen3 4B should NOT be treated as a vision model in the primary translation pipeline.

OCR supplies the visual information.

Qwen receives text.

The prompt should emphasize:

* preserve meaning
* natural translation
* correct technical terminology
* do not add explanations
* do not omit important information
* preserve names/acronyms
* respect glossary
* return strict JSON
* do not return markdown
* do not return commentary

Example conceptual instruction:

You are a professional Japanese-English technical translator.
Translate the supplied text from the source language to the target language.
Requirements:
- Preserve meaning accurately.
- Prefer natural professional language.
- Respect the supplied terminology glossary.
- Do not add explanations.
- Do not omit information.
- Preserve technical acronyms.
- Return ONLY valid JSON.

The application must use structured requests containing region IDs.

Example:

{
  "source_language": "Japanese",
  "target_language": "English",
  "style": "Business",
  "items": [
    {
      "id": "region_001",
      "text": "今後のプロセス安全活動について"
    }
  ]
}

Expected:

{
  "translations": [
    {
      "id": "region_001",
      "translation": "Future Process Safety Activities"
    }
  ]
}

The parser must tolerate harmless formatting problems where reasonably possible.

However, do not silently accept completely malformed responses.

17. TRANSLATION CACHE

Caching is mandatory.

The application must NOT repeatedly translate identical text.

Cache key should be based on:

normalized source text
source language
target language
translation style
glossary version

Hash using SHA-256.

Example conceptual key:

SHA256(
    normalized_text
    + source_language
    + target_language
    + style
    + glossary_version
)

Use SQLite for persistent local caching.

Cache hit:

OCR
 ↓
cache HIT
 ↓
instant translation

Cache miss:

OCR
 ↓
cache MISS
 ↓
Qwen
 ↓
store
 ↓
display

Do not store screenshots in the cache.

19. SPATIAL TRANSLATION OVERLAY

  "text": "今後のプロセス安全活動について",
  "bbox": [420, 180, 780, 220]

Future Process Safety Activities

[420,180,780,220]

Preferred placement order:

1. directly below source
2. directly above source
3. right side
4. left side
5. within/over source area only when necessary

The renderer must check:

* screen boundaries
* available space
* nearby translation boxes
* overlap with other translations
* monitor boundaries

The translation should visually appear associated with the source.

今後のプロセス安全活動について
Future Process Safety Activities

41. LLM BATCHING

Do not call Qwen separately for every word.

Batch related OCR regions.

Example:

{
  "items": [
    {"id": "r001", "text": "..."},
    {"id": "r002", "text": "..."},
    {"id": "r003", "text": "..."}
  ]
}

Return:

{
  "translations": [
    {"id": "r001", "translation": "..."},
    {"id": "r002", "translation": "..."},
    {"id": "r003", "translation": "..."}
  ]
}

This reduces:

* API overhead
* model initialization overhead
* latency
* token overhead

and works well with Qwen3 4B.

+

* entire session history

For context-sensitive translation, use only relevant nearby text.
